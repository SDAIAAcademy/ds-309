# Responsible Data Science: Privacy, Fairness and Documentation: labs

Sixteen notebooks, one per session, on the synthetic data of Yusr Housing Support Fund, and a
capstone on a second synthetic case. Every lab runs on a laptop CPU or in Google Colab. No lab
calls a model API or downloads a model.

## Quick start

- **Google Colab:** open a notebook from the table below or from the course page; its first cell
  clones this repository and installs `requirements-colab.txt`.
- **Locally:** install [uv](https://docs.astral.sh/uv/), clone the repository, then from `labs/`:

  ```
  uv sync
  uv run jupyter lab
  ```

  `uv.lock` pins every library version used when the reference results were produced.

Run [`00_setup_check.ipynb`](00_setup_check.ipynb) once before Day 1: it imports every library,
reads one data file and prints what is missing.

## How the labs work

- **Every lab starts from a supplied reference state** in `data/`, never from another lab's
  output. If you missed a session, the next lab still runs.
- **Exercises** are functions that raise `NotImplementedError` until you write them. The cell after
  each exercise has a safety net: if the exercise is not done, it loads the reference result from
  `data/reference/` and says so, so that the rest of the notebook still runs.
- **Checks** print ✅ when a result meets the lab's rule, and stop with "not yet" when it does not.
- **Outputs** go to `artifacts/<lab>/`, which you may keep for the capstone.
- **Quick mode:** set `YUSR_QUICK=1` to run Labs 2.2, 2.3 and 2.4 with fewer repetitions and smaller samples, for a
  first pass on a slow machine.
- The reference versions are in `solutions/`.

## The data

All data is synthetic, generated by `prepare_data.py` with the fixed seed 309; no row describes a
real person, and every national identifier and mobile number carries the marker `SYN`. To write the files again:

```
uv run python prepare_data.py
```

| File | Used in |
|---|---|
| `applicants.csv.gz`: 60,000 applications with identifiers, notes, income and decisions | Days 1 and 2 |
| `release_a_research_extract.csv.gz`, `public_register.csv` | Day 1, linkage |
| `ahliya_train.csv.gz`, `ahliya_scored_test.csv`, `ahliya_validation_report.json`, `ahliya_deployment_log.csv`, `income_audit.csv`, `audit_findings.json` | Day 3 |
| `release_log.json`, `risks.json`, `peer/` | Day 4 |

## For maintainers

The notebooks are generated from the percent-format sources in `_src/` by `_tools/py2nb.py`
(`uv run python _tools/py2nb.py` from `labs/`), which also writes the solutions to `solutions/`.
Edit the sources, not the notebooks. The reference results in `data/reference/` are written by
running a source with `YUSR_WRITE_REF=1`.
